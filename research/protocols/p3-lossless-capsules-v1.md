# Lossless low-rank prediction plus residual: finite packaging supplement

Declared after approximate adapter calibration/confirmation but BEFORE measuring residual patch sizes. This is a data-informed engineering follow-up, not independent behavioral confirmation or a claim of a new compression algorithm. Candidate ranks fixed16,32,64; no extra target inference, scored tokens, training or model-quality selection. Compare total delivery bytes (existing factor package + exact residual archive) against the previously measured20.3MB exact base-to-Fable patch. Count all metadata and required factor/residual files; the matching base is required and excluded.

Predict intermediate weights from the same pinned aligned parent and F16 factor package. Floating BLAS reconstruction can depend on summation/kernel choices, so it is NOT a portable predictor guarantee. Instead, represent each F16 factor as an exact integer times2^-24; accumulate products in int64; add the base at scale2^-48. Reject unless an absolute bound proves every intermediate fitsint64 and every resulting numerator is exactly representable in float64 (magnitude<2^53). Convert that exact dyadic value once toF16. Fixed arithmetic, rather than a favorable BLAS build, determines the predictor file. Preserve untouched bytes/metadata and exact sparse corrections; merge into a new ignored GGUF.

Use the established named-tensor XOR/deflate codec from that deterministic predictor to the ORIGINAL Fable target, including exact metadata/layout. Reconstruct and require complete target SHA256 identity. Thus the delivered result can be lossless even when the low-rank predictor alone is approximate. Report predictor time, residual bytes, factor bytes, total bytes, exact restoration and all failures. A numerical residual is stored data, not a newly trained model. Three predictor+restore pairs add<3GB; cap additional binary outputs5GB. Never overwrite previous approximate packages or reinterpret their quality results.

Validate exact integer arithmetic against a scalar integer reference and reject overflow/inexact conversion cases. Record all three fixed candidates even if combined size fails the5MB aspiration. A file-identical restoration needs no redundant model-quality benchmark: it is the already evaluated original artifact. The result is an exact delivery case study; broader compression/novelty claims need more models and relevant specialized lossless baselines.
