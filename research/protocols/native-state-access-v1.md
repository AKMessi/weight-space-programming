# Native final-state compatibility gate

Declared before these diagnostic calls. The fixed attenuation pilots found no eligible repair; before treating directional/component methods as unavailable, test whether the existing native runtime exposes a verified final readout state without PyTorch. This is a compatibility gate, not a newly claimed editing method or an independent quality benchmark.

Two visible calibration contexts (JSON-only extraction and requested code/explanation) per floating architecture. Collect one next token and its 20 pre-sampling log probabilities with temperature 1, no top-k/top-p/min-p truncation and no repetition penalty. Obtain the exact rendered prompt and match tokenization to the recorded native chat prompt length. In a separate owned embedding-only server using last pooling, request the raw unnormalized state through `/embedding` with `embd_normalize=-1`; the OpenAI-style embedding endpoint normalizes and is unsuitable for this check.

Read the existing output matrix (tied token embeddings if no output tensor exists), compute its FP32 product with that state, and compare centered logits for the native top-20 token IDs. Pass requires equal top-1, maximum centered error <=0.05, and relative centered error <=1%. Publish every raw request/response, discrepancy, error and exclusion. This establishes only the tested boundary in two contexts; it is not a guarantee on other layers, inputs or backends.

Ceilings: six generated tokens across three generation runs, at most 10,000 diagnostic prompt/scored tokens under the existing one-million ceiling. Use a separate append-only scored-token reservation ledger. One model resident; existing floating sources, full offload where previously used and 18 layers for ordinary LFM3. No training, external API or new model download. Any further directional-edit pilot needs a fresh frozen protocol/data before candidate feedback; do not reuse inspected confirmation outcomes as a new held-out test.
